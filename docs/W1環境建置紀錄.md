### 官方 codelab `qsti-qemu-on-wsl` 重點(GitHub qnx/codelabs,11/13 讀取)
- 只要 `wsl --install`(預設 WSL2 + Ubuntu 24.04),**沒有要求改 `.wslconfig`**
- 套件:`qemu-system qemu-system-x86 qemu-kvm libvirt-daemon-system libvirt-clients bridge-utils virt-manager`
- 網路:`libvirtd` + `virsh net-start default` 產生 virbr0;`/etc/qemu/bridge.conf` 寫 `allow virbr0`(root:kvm、640)
- QEMU 參數:`--enable-kvm`、`-netdev bridge,br=virbr0`、`virtio-net-pci`、`-nographic -serial mon:stdio`;**Intel 要加 `--cpu host,host-phys-bits-limit=39`**
- codelab 範例用 `-smp 4 -m 8G`(以 16 GB 主機為前提),本機要降到 `-smp 2 -m 1536M`~`2G`,且不需要 `virtio-vga-gl` / SDL 圖形(精簡無介面映像)
- codelab 用的是 QSTI(Quick Start Target Image,含圖形介面);規劃書 E4 改用 `mkqnximage` 建精簡映像,QEMU 參數的網路、KVM、CPU 部分照搬

### 擬定的 `.wslconfig`(待使用者同意)
```ini
[wsl2]
memory=5GB
processors=4
swap=4GB
nestedVirtualization=true
```
- `nestedVirtualization` 在 Windows 11 預設就是 true,明寫是為了可追溯
- `memory=5GB` 是原開發主機的設定，ASUS 從 4 GB 的 WSL2 上限起測。

## 2026-11-13 E1 安裝過程
1. 已寫入 `%UserProfile%\.wslconfig`(內容同上,D8)
2. `wsl --install -d Ubuntu-24.04 --no-launch`(UAC 提權)→ **失敗**:「參數錯誤。不正確發佈名稱:'Ubuntu-24.04'」
   - 原因:build 22000 內建的舊版 wsl.exe,`wsl --list --online` 只列 `Ubuntu`、Debian、kali-linux、OracleLinux_7_9/8_10/9_5、SLES 15 SP6、openSUSE-Tumbleweed,**沒有帶版本號的 Ubuntu**;`Ubuntu` 可能已指向 26.04,不能保證是 24.04
3. 改成兩段式:`wsl --install --no-distribution` → 成功,裝好「虛擬機器平台」與「Windows 子系統 Linux 版」,**需要重開機**
4. 重開機後要做:`wsl --update`(更新到 Store 版 WSL)→ `wsl --install -d Ubuntu-24.04` → 使用者自己設定 Linux 帳號密碼 → E2 檢查 `/dev/kvm`

## 2026-11-18 ASUS VivoBook X409JP E1–E2 驗收

- **Ubuntu 24.04(本機實測)**。`ubuntu-24.04.5-wsl-amd64.wsl` 的 SHA-256 `bb415d82…6039e` 與 Canonical `SHA256SUMS` 一致。以 `wsl --install --from-file … --name Ubuntu-24.04 --location D:\WSL\Ubuntu-24.04 --no-launch` 安裝，`wsl -l -v` 顯示 VERSION 2，VHDX 位於 D 槽。Ubuntu 24.04.5 LTS，systemd 已啟用，`.wslconfig` 生效(4 處理器、可見記憶體 3.8 GiB、swap 2.0 GiB)。
- **主機套件**。安裝 E2 套件清單，`cmake` 3.28.3、`qemu-system-x86` 8.2.2。
- **E2 KVM(本機實測)**。`/proc/cpuinfo` 有 `vmx`;`/dev/kvm` 為 `crw-rw---- root kvm`，使用者加入 `kvm` 群組後可讀寫。`qemu-system-x86_64 -accel kvm -cpu host … -S` 的 monitor 回報 `kvm support: enabled`。後續 QNX 開機可用 KVM 加速。
- **E7 F Prime 工具(本機實測)**。`~/src/fprime-qnx` 位於 `000baec2`;`~/src/fprime-upstream` 為 v4.4.2(`f22ce8f2…`)，GoogleTest 子模組 `58d77fa8…`。在 `~/.venvs/fprime-qnx`(Python 3.12.3)以 `pip install --no-index --find-links /mnt/d/WSL/installers/fprime-python-cp312-linux-x86_64 -r requirements.txt` 離線安裝成功:`fprime-tools` 4.4.0、`fprime-gds` 4.4.0、`fprime-fpp` 3.4.0、`cmake` 3.26.0、`ninja` 1.11.1.4。`fprime-util --help` 與 `fpp-check` v3.4.0 可執行。

## 2026-11-19 ASUS VivoBook X409JP E3–E5 驗收

- **QNX 授權**。myQNX 帳號取得 QNX SDP 8.0 非商用授權（Named User）。要先在 License Manager 的 Users 欄把授權部署給自己，個人頁的 Registered Products 才會出現，QSC 下載頁也才不再要求 Product Serial/Password。只接受授權、未部署給使用者是不夠的。授權序號不寫進 repo。
- **E3 QNX Software Center 與 SDP(本機實測)**。`qnx-setup-2.0.4-202501021438-linux.run`(Makeself 內建 MD5 檢查通過)裝在 Ubuntu 的 `~/qnx/qnxsoftwarecenter`。安裝程式結束後 WSL 工作階段一併結束，QSC 視窗也跟著關閉，所以改從終端機前景執行 `~/qnx/qnxsoftwarecenter/qnxsoftwarecenter`(WSLg 視窗)。在 QSC 選 **QNX Software Development Platform 8.0.6**(patchset806,GA 2026-11-12)，預設套件全選，安裝到 `~/qnx800`(3.6 GB)。`qcc -V` 列出 GCC 12.2.0 的 `gcc_ntox86_64`(預設)與 `gcc_ntoaarch64le`。`$QNX_TARGET/etc/qversion` 仍顯示 `8.0.0`,kernel 建置日期為 2026/10/30。
- **E5 網路(本機實測)**。E2 只裝了 QEMU,所以另外安裝 `libvirt-daemon-system` 10.0.0、`libvirt-clients`、`bridge-utils` 1.7.1、`dnsmasq-base`。libvirt 的 `default` NAT 網路設為 active + autostart,`virbr0` 位址 192.168.122.1/24。依官方 codelab 寫入 `/etc/qemu/bridge.conf`(`allow virbr0`,root:kvm 640),並對 `/usr/lib/qemu/qemu-bridge-helper` 設定 setuid。
- **E4 映像與開機(本機實測)**。在 `~/qnx/images/smoke` 執行 `mkqnximage --noprompt --type=qemu --arch=x86_64 --cpu=2 --ram=1536M --hostname=qnxvm --ssh-ident=$HOME/.ssh/qnx_vm.pub --build --run=-h`。runimage 偵測到 `/dev/kvm` 可寫，使用 `--enable-kvm --cpu host`。序列埠紀錄到 `Startup complete`,`QNX qnxvm 8.0.0 2026/10/30-09:10:05EDT x86pc x86_64`。guest 透過 DHCP 取得 192.168.122.2;`pidin info` 顯示 2 顆 CPU、可用記憶體 1366/1535 MB。
  - `--run=-h` 讓 QEMU 在背景執行，但 stderr 沒有導走。外層若接 `| tail` 會一直卡住等待，腳本裡不要把這行接到管線。
- **E4 Hello World(本機實測)**。`qcc -Vgcc_ntox86_64 -O2` 編出 x86-64 QNX 執行檔(interpreter `/usr/lib/ldqnx-64.so.2`)，用專用金鑰 `~/.ssh/qnx_vm` 以 root scp 到 guest 後執行，輸出 `Hello from QNX: QNX qnxvm 8.0.0 x86pc`。`mkqnximage --stop` 可正常關機。
- **待辦**。E6 apk sysroot(mlpack、armadillo、openblas);F Prime 工具鏈接上 qcc,讓上游 `Ref` 在 QNX 上建置(里程碑 M1)。
