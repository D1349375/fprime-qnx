## Development-revision recheck

| Area | Verified scope and candidate work |
| --- | --- |
| U0 platform integration | The Ref command, events and rate-group telemetry were verified on the project's pinned release in the x86-64 guest. The upstream development revision was reviewed separately. [Ref evidence](evidence-index.md#target-and-host-coverage) |
| U2 optional Rust in Ref | The current development Ref still includes `wasmSeq` and stops at configuration without Rust 1.87 or newer. Framework builds without Rust skip only the WebAssembly sequencer. Maintainers chose this fail-fast requirement in #6034 and merged it in #6212. The sequencer's CMake already reads `RUST_TARGET_TRIPLE` from a cross-compile toolchain. The Rust QNX 8.0 targets are Tier 3 without prebuilt standard libraries, which is why this port omits `wasmSeq`. No upstream report is planned. [Prior issue #6034](https://github.com/nasa/fprime/issues/6034) · [Merged PR #6212](https://github.com/nasa/fprime/pull/6212) · [Reviewed Ref CMake](https://github.com/nasa/fprime/blob/633c89d5b7f67a547160712a38efa58047566512/TestDeploymentsProject/Ref/CMakeLists.txt) |
| U4 POSIX UART | With SDP 8.0.6 and `q++ -Vgcc_ntox86_64`, standalone header probes confirmed that `CRTSCTS` and `B230400` are unavailable and that `IHFLOW \| OHFLOW` compiles. The complete driver, fallback behavior and physical UART remain unverified. [Driver](https://github.com/nasa/fprime/blob/633c89d5b7f67a547160712a38efa58047566512/Drv/PosixUartDriver/PosixUartDriver.cpp) · [Related issue #5698](https://github.com/nasa/fprime/issues/5698) · [Related PR #5811](https://github.com/nasa/fprime/pull/5811) |
| U3 POSIX IP configuration | With SDP 8.0.6 `q++`, a QNX-only build of the five `Drv_Ip` sources stops at the OS guard in `IpCfg.hpp`. The sources compile with the Linux definition, or with a project override of `config/IpCfg.hpp` that adds QNX. Upstream made that file the override point for new platforms, so no upstream report is planned. The pinned v4.4.2 release also guards the individual sources, so this port keeps its Linux definition. Linking and target TCP/UDP on the development revision remain unverified. [Reviewed IP source](https://github.com/nasa/fprime/tree/633c89d5b7f67a547160712a38efa58047566512/Drv/Ip) · [Upstream PR #6122](https://github.com/nasa/fprime/pull/6122) · [Platform definitions](../../FprimeQnx/cmake/platform/QNX.cmake) |
| U1 OSAL tests | The unmodified development-revision `Os` unit tests ran in a new x86-64 guest with a QNX platform definition and no Linux definition. 25 of 28 suites passed. The three failures come from test assumptions: free space on `/`, `std::chrono::system_clock` resolution, and the C library's `assert()` text. The task findings from v4.4.2 no longer apply. The RawTime suite also needs a project override of `config/RawTimeSource.hpp`, the intended override point, which is not reported. [Issue #6438](https://github.com/nasa/fprime/issues/6438) · [Reviewed `Os` source](https://github.com/nasa/fprime/tree/633c89d5b7f67a547160712a38efa58047566512/Os) · The [local portability patch](../../adoption/osal-test-portability.patch) is for v4.4.2. |
