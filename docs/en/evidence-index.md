## Frozen E5 target checks

Ref used a clean clone and a fresh cross-build and image. The GDS retry on that image returned both NO-OP events and rate group 1 telemetry. ADCS used a separate clean build. Its first guest stalled before SSH readiness. The retry on the verified Ref image confirmed the kernel death event, FDIR, the SLM replacement PID, fresh-session adoption, rate group telemetry and reconnection. The trained-advisor pair runner used the same project source in a dedicated guest. The first short run produced the reusable test image and held-out replay. The repeat used a copy of the stopped image and stalled before SSH. The formal cohort used a new copy of that image and one fixed QEMU CPU profile for both arms. ## Trained-advisor recovery

Follow the [M4 trained advisor or paired run](reproduce.md#m4-trained-advisor-and-dataset). Check the recorded revision, guest and model before reading the verdict. The [SLM template](https://github.com/D1349375/fprime-qnx/blob/d96c9f5a3696e620c65c507f7552f2d9c007cb78/FprimeQnxReference/qnx/m3-slm.xml.in#L11-L18) sets the advisor repair policy. The paired harness checks the rendered policy field against the matched guest, model and workload.

For a restart case, check the advisor's exit and replacement identity, FlightSW's FDIR fallback, the revoked-session rejection (`R2_SESSION`), and the first accepted result from the replacement session. The offline replay supplies the corresponding expected inference. Use the existing checkers in the run's M4 Python environment.

```bash
read -r -p 'M4 run directory: ' m4_run_dir
read -r -p 'Restart case directory: ' case_dir
"$M4_PYTHON" -B FprimeQnxReference/test/int/check-m3.py "$case_dir"
"$M4_PYTHON" -B FprimeQnxReference/test/m4/assess-adcs.py "$m4_run_dir/replay" "$case_dir"
```

`check-m3.py` verifies the full fault contract and can report a failed or inconclusive run. `assess-adcs.py` checks the live inference against replay. Keep both original verdicts and the detailed run evidence. Use the [application behavior summary](reproduce.md#m4-paired-repair-policy-check) for the restart behavior. The frozen run's [application behavior summary](results.md#frozen-e5-restart-behavior) links to the recorded recovery checks. The pre-freeze rehearsal used [a prior E2 source](https://github.com/D1349375/fprime-qnx/commit/d96c9f5a3696e620c65c507f7552f2d9c007cb78).
