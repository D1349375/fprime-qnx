
# Limitations

| Area | Current coverage |
| --- | --- |
| QNX runtime | QNX SDP 8.0.6 with `qcc` GCC 12.2.0, QNX 8.0.0 x86-64 on QEMU/KVM under Ubuntu 24.04.5 and WSL2. |
| AArch64 and hardware | Ref and the `FprimeQnx` platform library, including the native CPU and memory OSAL, cross-build with the [`qnx-aarch64le` toolchain file](../../FprimeQnx/cmake/toolchain/qnx-aarch64le.cmake) at `70db8bb`. The result is a 64-bit AArch64 executable with the QNX interpreter. [Cross-build](reproduce.md#ref-aarch64-cross-build) The ADCS deployments need an AArch64 ML sysroot that `main` does not provide, so their AArch64 build is not part of this release. AArch64 execution and physical QNX hardware are unverified. |
| Flight scheduling | In repeated runs in the nested WSL2/QEMU setup, the project's flight deadline checker occasionally recorded a missed cycle. The project attributes this to stalls of the WSL2 virtual machine while it hosts the nested guest. The project publishes no evaluation of QNX timing and no timing figures. [Decision D95](../zh/決策與變更紀錄.md#d95--apply-the-organizer-reply-on-qnx-evaluations-2026-11-28) The flight timer uses a fixed-priority channel in every mode. [Decision D75](../zh/決策與變更紀錄.md#d75--integrate-e7-guard-the-drift-estimate-and-pre-register-the-acceptance-round-2026-11-25) A single-layer WHPX guest did not boot. [Decision D71](../zh/決策與變更紀錄.md#d71--attribute-the-missed-releases-to-the-wsl2-virtualization-layer-2026-11-25) The checker evaluates every planned release against the configured deadline for its own run. The paired summary reports application recovery behavior. Each original timing verdict remains in the local evidence and applies to its own case. The formal cohorts used one QEMU CPU profile with TSC deadline disabled. Native Linux/KVM and physical timing coverage remain open. |
| OSAL | `Os::Cpu` and `Os::Memory` use native QNX statistics. The x86-64 guest has native coverage. The suite table separates stub coverage, unsupported Linux-only task cases, the target file test skipped without `/dev/full`, and the ThreadSanitizer suite outside the QNX run. [OSAL results](results.md#osal-v1) |
| Deployment components | The port excludes the stock POSIX UART driver from QNX builds because the SDK headers lack the two symbols it uses. The Ref example omits the Rust-backed `WasmSequencer` and keeps `cmdSeq`. [Upstream status](upstream.md) |
| ADCS and ML | Dynamics and coarse sun sensors are simulated. The learned advisors cover one fixed positive bias and one slow positive drift on the +X sensor. In the drift comparison the conventional residual warned before the FFN. FlightSW withholds its estimate during an unconfirmed residual warning. The detector and independent FDIR first alerted on the same cycle in the recorded exercise. The example exercises subsequent sensor isolation and recovery. OPS-SAT telemetry is a separate offline exercise. [Application results](results.md#trained-advisor-and-offline-replay) |
| Ground and fault monitoring | GDS services run in FlightSW on separate threads from the periodic estimation work. With native IPC and GDS enabled, FlightSW reports the watched advisor's `ProcessDied` event along with FDIR engagement, session changes and control source. Non-root subscription policy and overlapping advisor handovers remain unverified. |
| Authority and safety | FlightSW owns the ADCS decision. The Gate authorizes a limited sensor exclusion and the estimator can return a degraded state. Spacecraft-wide safe mode remains outside the advisor interface. This is a simulated engineering reference with no safety certification. |
| Hosted CI | The Ubuntu workflow checks publication scope, shell and Python sources, RecoveryGate logic, report fixtures and internal links. QNX build, boot and runtime validation use the local SDK and guest. [Workflow](../../.github/workflows/host-checks.yml) |
