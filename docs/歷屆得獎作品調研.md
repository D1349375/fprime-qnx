> 調研日期:2026-11-12
> 本文件只列查到的事實,不含方向建議。

## 0. 先講清楚:「歷屆」指的是什麼

**QNX Global Hackathon 2026 是第一屆**(2026-11-02 首次舉辦),沒有前一屆的同名比賽。

所以「歷屆得獎作品」指的是 **QNX 過去在其他黑客松贊助的 QNX 專屬獎項**。這是 QNX Everywhere 計畫(2024 年底起把 QNX 8.0 免費開放給非商業使用)推動的校園黑客松系列,評審同一批人:本屆評審 John Hanam(Dev Relations)、Andy Gryc(Dev Ecosystem)、Patrick Murtha(Product)、Morgan McKeen(Developer Engagement Marketing)也是那些場次的 QNX 評審與部落格作者。

### 與本屆的格式差異(查證事實)

| 項目 | 過往贊助場次 | 本屆 Global Hackathon |
|---|---|---|
| 時長 | 24–36 小時,實體 | 6 週,線上 |
| 硬體 | 現場發 Raspberry Pi 4B/5 套件、借感測器 | 自備;QEMU 也可以 |
| 獎金 | 單一 QNX 獎約 US$500–1,000 禮券 | 總獎金 US$50,000,單獎最高 US$10,000 |
| 評審依據 | 現場 demo + Devpost 頁 | YouTube 影片(<3 分鐘)+ repo + 文字說明 |
| 類別 | 多半只分「Hardware / Software」 | 五類:Robotics & Medical / Automotive / Low-level / Tooling / Ports |
| 參賽者 QNX 經驗 | 多數當週末才第一次接觸 QNX(官方部落格原話) | 不限 |

## 3. 跨場次整理(從上面作品歸納的事實)

### 3.1 QNX 獎題目的演變

| 時期 | QNX 獎項名稱 / 敘述 |
|---|---|
| 2025 | 「Hardware Project」/「Software Focus」/「Best Use of QNX」 |
| 2026 下半 | Hack the 6ix 2026:「打造用 QNX RTOS 的 **AI 嵌入式系統**」;Hack the North 2026:「用 QNX 打造**使用 AI** 的嵌入式系統」 |

本屆評分標準第四項也是「Innovation & **AI** Creativity」。

### 3.2 得獎作品的領域分布(約 22 件 QNX 獎得主)

| 領域 | 作品 |
|---|---|
| 醫療 / 照護 / 健康 | Praxis、Rocko、Blissey Beacon、Quark(開車疲勞)、Plantr(植物) |
| 機器人 / 實體控制 | QNXMobility、Puck Buddy、Project AMPM、Buzzkill |
| 安全 / 工業監控 | SafeTank、Vanguard Telematics、Vibrado |
| 穿戴 / 互動 | Combadge、SpideyIRL、Beats by Air |
| 娛樂 / 創意 | Paper DJ、QNX Fighter |
| 開發工具 / 系統工具 | QNXtainer、RPM、QNX-RasPi-Setup-Util |

### 3.3 QNX 評審在部落格明確稱讚過的點(原文整理)

- 用到 **QNX RTOS 的特性**:多執行緒、thread priority、即時排程(Beats by Air)
- **端到端完整度**、像產品而不只是 demo(QNXtainer、RPM、Plantr)
- **有商業化策略**(Plantr)
- **架構文件寫得完整**(QNXtainer)
- **沒有範例也自己克服硬體整合**(Plantr、QNX Fighter)
- **解決 mission-critical 的真實問題**(Rocko 專文)

### 3.4 AI 在 QNX 上的實際跑法(得獎作品實例)

| 跑法 | 實例 |
|---|---|
| 裝置端小型 LLM | Praxis(llama.cpp + Qwen2.5-0.5B 量化)、Quark(llama.cpp) |
| 裝置端 CV / 語音模型 | Rocko(Whisper + MobileNetV2 TFLite)、Puck Buddy / Buzzkill / Paper DJ(OpenCV)、Surgy(mlpack 異常偵測) |
| QNX 管即時,AI 放另一台機器 | SpideyIRL(QNX Pi + Linux Pi)、Sixth-Sense(QNX Pi + 筆電)、Surgy(QNX 與 VR 兩條獨立路徑) |
| QNX 管感測,雲端 LLM 做推理 | Combadge(GPT)、Fridge Mind / 6ixenality(Gemini)、Vanguard(OpenAI + Fetch.ai) |

### 3.5 有用到 QNX 原生機制的得獎作品(對應本屆「Best Use of QNX-specific Technologies」列舉項)

| 機制 | 作品 |
|---|---|
| Resource manager | Paper DJ(`/dev/paperdj`) |
| Native message passing / channels | Puck Buddy(named channels)、Paper DJ(write → message) |
| 即時排程(SCHED_FIFO / SCHED_SPORADIC / priority inheritance) | Paper DJ、Beats by Air |
| Boot 客製化 | Paper DJ(開機腳本啟動) |
| Screen API(原生圖形) | QNX Fighter |
| Camera / Sensor API | Puck Buddy、Paper DJ |

多數得獎作品對 QNX 的使用停留在「跑在 QNX 上 + 讀感測器」;明確寫出 QNX 原生 IPC / resource manager / 排程策略的只有上表幾件。

### 3.6 硬體平台
所有查到的得獎作品都是 **Raspberry Pi 4B 或 5**(2026 年多為 Pi 5);沒有查到只用 QEMU 就得獎的過往作品。

## 4. 本屆目前已公開的參賽作品(截至 2026-11-12)

Devpost 搜尋「QNX」能看到約 **60 件**標記為 QNX Global Hackathon 的公開作品(還在進行中,這些不是得獎作品,只能反映目前公開出來的投稿)。依作品自述的標語分類:

### 開發工具 / 分析器(數量最多,約 40 件)
- **Kernel trace 分析 / 即時性除錯**:PulseGuard RT、kevscope、Pathfinder、QNX Trace Studio、QNX deadline debugger、Sendgraph(IPC deadlock)、Deadline CI(把 trace 變成 CI 時序測試)、jitterscope、ipcbench、PulseProof RT
- **Buildfile / 開機映像檢查**:QNX Build Inspector、BootLens、Boot Order Atlas、BootWeave、BootWave、QNXPulse Host Studio、SyntraVariga Build Guard、QNX Link Proof
- **映像安全 / SBOM**:ifscan、qbom、Sentinel for QNX
- **移植前掃描 / 移植工具**:qnx-portscan、QNXScout、qnx-port-doctor、PortPilot、QNX Crate Atlas(前 500 大 Rust crate 能否在 QNX 8.0 編譯)
- **給 AI coding agent 用的 QNX 工具**:qnx-mcp、QNX Host MCP(MCP server,讓 AI 助理能編譯並在 QEMU 上執行 QNX 程式)
- **測試 / 故障注入**:QNX Test Farm(QEMU 平行回歸測試)、qshim(驅動程式前的故障注入與錄放)、Faultline、QNX-ChaosPulse
- **靜態分析 / 健康檢查**:QNX Health Checker、QNX-RT-Inspector、G(E)A(L)L(形式驗證)、Blueprint

### 開源移植
- PX4 on QNX(無人機飛控;標語宣稱 CPU 過載下 800 Hz 控制迴路仍穩定,Linux 掉 21%)
