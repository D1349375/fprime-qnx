### I-04 · Codex 交叉建置官方 OSAL 測試（V1）

- **來源與前提** F Prime v4.4.2 和 GoogleTest 均使用 I-03 的固定 Git 版本，採用上游 POSIX、Generic Queue、共通 OSAL 和 CPU／Memory stub 測試。
- **第 1 次建置** GoogleTest 的獨立 target 取不到 QNX feature macro，報 `'isatty' was not declared in this scope`。POSIX Task 因相容巨集走到 Linux-only 分支，報 `fatal error: sys/syscall.h: No such file or directory`。
- **第 2 次建置** `FprimeQnx/library.cmake` 為 GoogleTest 加 `_QNX_SOURCE`，並對 `PosixTaskTest` 關閉 Linux 巨集後完成編譯，連結報 `cc: unknown option: '--coverage'`。
- **第 3 次建置** 加上 `-DFPRIME_ENABLE_UT_COVERAGE=OFF` 並使用 `--disable-sanitizers` 的目標端 build cache。17 個 x86-64 測試執行檔全數成功連結。見 `27bec2161384557eaa54e7a22d715d652f682897` 和 D13。

### I-05 · Codex 執行並診斷 QNX 客體的 OSAL 測試（V1）

- **第一次部署** 整批 SCP 寫到 `/tmp` 時出現 `scp: write remote …: Failure`。本機 17 個未裁切的執行檔約 96 MiB。客體 `/tmp` 指向 `/data/var/tmp`，`df` 顯示 `/data` 當時剩 56 MiB。改成逐組上傳、執行、清理，見 D15。
- **驗收版本** `72a891e9d0a9b947c982ae163e9851df46210b80`。使用 I-03 的 x86-64 客體，從同一 checkout 的 UT cache 重建後執行 `scripts/osal-check.sh`。
- **分母** 17 組執行檔均實際在 QNX 上運行，13 組通過、4 組含失敗。共 259 個 GoogleTest 案例，247 通過、11 失敗、1 跳過。`PosixFileErrorHandling.WriteNoSpaceSurfacesError` 因客體缺少 `/dev/full` 由測試跳過。
- **範圍** TSan 專用 Queue suite 未列入上述分母。CPU 和 Memory 各自的 stub suite 通過。原生 CPU／Memory 計量與 Linux 定義的 Task priority／nice 案例列為不支援。

| 失敗的 suite | 失敗案例 | 核對到的原因和後續檢查 |
| --- | ---: | --- |
| `PosixTaskTest` | 1 | `DefaultModeNiceBandPriorityRemainsSchedRr` 要求 priority 120 被截到上限。客體 `SCHED_RR` 範圍為 1–253，實測保留有效值 120。上游測試應以目標有效範圍計算預期值。 |
| `PosixFileSystemTest` | 2 | `GetFreeSpace` 與 `RandomizedTesting` 都在同一條斷言要求根目錄 free bytes 大於 0。`statvfs("/")` 確認只讀 IFS 的剩餘 blocks 為 0，`statvfs("/data")` 可取得大於 0 的可用空間。上游測試可用可寫掛載點作 fixture。 |
| `PosixRawTimeTest` | 7 | 共用測試把奈秒的 `clock_gettime` 結果和微秒的 `std::chrono::system_clock` 上界直接比較。客體測得 `system_clock::period = 1/1000000 s`，例如 raw 183790159 ns、upper 183790000 ns。7 個直接以同一時鐘取界的 POSIX／來源測試通過。 |
| `PriorityMemQueue_UnitTest` | 1 | `DoubleCreateAssertion` 的第二次 create 確實終止子行程，實際訊息含 `assertion failed`，測試要求大小寫相符的 `Assertion`。 |

- **證據** `adoption/logs/osal-check-*/summary.tsv`、各 suite 的 `.log`、`target-uname.txt`，以及這輪本機保存的 `v1-platform-probe.cpp`、`v1-platform-probe-target.log`。上游可攜性修正方向見 [upstream notes](upstream-notes.md)。
- **接續點** 優先確認上游 Task、檔案系統、時鐘比較與 assertion 訊息的測試契約，保留在 QNX 上可重跑的固定版本。M2 的 ADCS 參考部署與時序契約仍依規劃書 §11。

### I-06 · 讓 OSAL 驗收可重複執行

- **問題** 第一次跑完 V1 後，`/data/var/dumper` 已佔約 32 MiB，`/data` 只剩 18 MiB。在同一映像重新建置並執行時，`ulimit -c 0` 可以設定，但後續 `LocklessPriorityQueueTest` 和 `StubMemoryTest` 在 SCP 階段因空間不足而未能執行。見 `32224334f9b3caf89032947ce2431f2e77dfa59e`。
- **修正** `09abd68df82eb4aefa4c91d710b4b56d72f19929` 讓 V1 預設建立自己的映像與金鑰，為 `/data` 預留額外 128 MiB。保留逐組傳輸與清理。V2b 使用同一個 VM 建置 helper，仍以自己的獨立映像驗收。見 D12、D15。
- **複驗** 以新產生的 `fprime-osal` QNX 8.0.0 x86-64 客體完整重跑。17 組再次執行完畢，結果與 I-05 相同，247 通過、11 失敗、1 跳過。`LocklessPriorityQueueTest` 31 案例與 `StubMemoryTest` 3 案例均通過。
