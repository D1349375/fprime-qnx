## 二、要做什麼

### 硬性要求:作品必須「跑在 QNX 8.0 上」或「為 QNX 8.0 服務」

二擇一:
1. **跑在 QNX 8.0 RTOS 上的** 應用程式 / 驅動程式 / 函式庫 / 元件 —— 任何 QNX 支援的硬體皆可,**含 QEMU 模擬器**
2. **跑在主機端(Windows / macOS / Linux)的工具**,用來建置、測試、分析或支援 QNX 8.0 軟體

官方強調:**不需要實體硬體**,QEMU 可以,Raspberry Pi 5 也可以。

### 五個類別(送件時只能選一個)

| 類別 | 官方定義 |
|---|---|
| **Robotics & Medical** | 時序、安全或可靠性至關重要的即時應用 |
| **Automotive & Mobility** | 軟體定義車輛(SDV)及其他移動應用 |
| **Low-level Software** | 用 QNX Driver Development Kit 做的板級支援元件或裝置驅動程式 |
| **Developer Tooling & Host Tools** | 讓 QNX 開發更容易的工具(主機端或目標端) |
| **Open-Source Contribution & Ports** | 把既有開源專案移植到 QNX,或對 QNX 開源生態做上游貢獻 |

**Open-Source Ports 類別的額外規定**:須在繳件期內**新開一個 repo**,放移植層/patches、QNX build files、建置執行說明、文件;用 URL 引用上游專案,**不可直接交 fork**、不可把上游 commit history 複製進來。

### 新舊專案

- 須於 11/2 ~ 12/15 之間新做,**或**既有專案在 11/2 後有「重大更新」(並在說明中解釋更新內容)

### 官方主頁的題目引導語(原文意譯)

- 做一個以微秒而非毫秒反應的機器人
- 寫一個還沒人寫過的驅動程式
- 把你喜歡的東西移植到 QNX
- 做你一直希望存在的開發工具
- 「只要跑在 QNX 8.0 上,或幫別人為它開發,就算數」

### 「QNX 使用證據」(Stage One 過關門檻)

送件說明必須講清楚專案**怎麼用到或支援 QNX**,並指出對應的檔案/函式/輸出/demo 讓評審能驗證。可接受的證據(列舉非窮盡):
- QNX 專屬原始碼或 API
- QNX 函式庫、標頭檔、buildfile、toolchain、system image、設定檔
- 在 QNX 8.0 上運行的 demo
- 主機端工具:專門為 QNX 8.0 做建置/分析/測試/部署/除錯/管理的輸出或功能

POSIX 相容程式碼、直譯式語言、既有軟體移植、跑在其他 OS 的工具都可以,**前提是清楚展示與 QNX 的實質連結**。Repo 必須證明「真的能在 QNX 8.0 上建置或運行」,不能只是 README 寫了 QNX。

## 四、評審方式

### Stage One:Pass/Fail
專案是否合理符合主題、合理使用指定的 API/SDK(即 QNX 8.0)。

### Stage Two:四項**等權重**評分

| 評分項 | 官方題目 |
|---|---|
| **Technological Implementation** | 做得多扎實?多有效地使用 QNX 8.0?程式碼是否反映真實工程投入、是可運作且非 trivial 的實作、真的在 QNX 上建置/運行? |
| **Design** | 是否交付完整、連貫的產品體驗,而不只是技術 PoC? |
| **Potential Impact** | 是否具體可信地說明它解決了 QNX 所服務或想進入之市場的真實問題?是否說明**為什麼即時作業系統(如 QNX)是正確的基礎**? |
| **Innovation & AI Creativity** | 是否是創意、非顯而易見的 QNX 用法?團隊是否展現對該問題領域的真正理解? |

- 同分時依上表順序比較單項分數(Technological Implementation 最先)
- 規則註明評審過程**可能使用 AI 自動分析**輔助
- 社群投票(Community Choice)另計,不影響評審分數

一件作品最多拿:**1 個 Overall 獎 + 1 個 Bonus 獎 + 1 個 Community Choice**。

### 兩個加碼獎細節
- **Best Codelab / Tutorial**:提交一份在繳件期內撰寫、教人在 QNX 8.0 上(或為 QNX 8.0)完成某項任務的 codelab/教學;**不需要跟主作品相關**;依同樣四項標準評選。須先有一件合格主作品。
- **Best Use of QNX-specific Technologies**:最有創意/影響力/深度地使用 QNX 獨有能力,官方列舉:
  - native message passing(原生訊息傳遞)
  - resource managers
  - microkernel 架構
  - startup / boot 客製化
  - real-time services
  - security policies
